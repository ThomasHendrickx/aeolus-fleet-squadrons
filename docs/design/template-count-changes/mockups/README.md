# Changing a template's ship count: screens

Docs only. [Issue #43](https://github.com/ThomasHendrickx/aeolus-fleet-squadrons/issues/43). Thomas approved S0 (the purpose), the screen decisions S2 to S5 and D1 to D5 at d22c3db ([template-count-changes.md](../template-count-changes.md), status). Where the page lives (S1) and how squadrons knows the template owner (S1a) are not decided, Thomas then chose a page Squadrons serves itself for S1. These screens draw that page and its entry from the console. S1a, who may open the page (R1) and how the owner-only call is authorised (R2) stay open. The behaviour they show is the approved picks. Thomas approved the remaining Squadrons page screens at 34b2a83 (the design's status): every state below is approved as a screen. The core compatibility they rely on, implementation and rollout are not.

**Simulated.** Everything here is drawn, not built. The data, people and ships are invented. No squadrons call, count, claim or page exists yet, and the buttons do nothing. **Assumed only to draw:** squadrons knows the signed-in person's ship (S1a option 1, not decided). The console link is a proposed aeolus-fleet change (E1), and Squadrons in the switcher assumes a manifest (E2). These screens do not decide who may see the page or how the fleet names a template owner. Approving them approves no identity, API or rights change (S1 and S1a in the design). The no-owner screen's words assume S1a option 1, a template owner that is a person ship.

[screens.html](screens.html) stands alone: it carries aeolus-fleet's `packages/ui/src/tokens.css` and its Geist fonts, from aeolus-fleet main on 12 Nov 2026. To preview it, open the file in a browser, or serve the folder with `python3 -m http.server 8043 --directory docs/design/template-count-changes/mockups` and open `http://localhost:8043/screens.html`. Each PNG is one frame of that file, rendered whole in Chromium at 1x: desktop 1440 wide, phone 375, light and dark.

The before is the console's template page as built today (`TemplateView`). The after is Squadrons' own page in the shared Aeolus header (`AppHeader`: fleet and app switcher, search, avatar menu), with the approved change card.

After a lost answer, reading the count again shows the approved screen if the approval was written, or the arriving screen if it was not. When the sign-in also ended, the page shows no count until the person signs in again. It then shows `return-written` or `return-not-written` only when squadrons answers for that one approval by its own decision key, a proposed contract with no call today. Otherwise it shows `return-unknown`. Nothing is replayed. "Nothing was written" appears only where squadrons refused this request before any write, under a proposed server contract that is not built. It never covers an earlier send of the same key (api-and-identity.md, C1 and P1).
